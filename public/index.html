What "real" means here
  • Real plan - the agent reads the live sign-up page and quotes the exact selectors it found.
  • Real code - you see the generated Playwright test before anything runs.
  • Your approval - nothing runs until you say go.
  • Real proof - each approved test runs twice in a real browser, with timing and an explanation in plain words.

How it works

Four steps. You stay in charge the whole way.

1

You describe

"Sign up and see my dashboard." Plain words are enough - no selectors, no code.

2

Agent studies the live app

It fetches the real page, lists the fields it found, and drafts a plan plus a Playwright test from selectors that exist right now.

3

You approve

Read the plan and the code. Nothing runs until you press approve - and you can decline.

4

Proof, twice

The test runs in a real browser, then again to check it is stable. You get pass/fail, timing, and a plain-English explanation.

Guardrails

  
What the agent will and will not do.

  

    
Human approval gate
No test ever runs without a person pressing approve. Declining is always allowed.

    
Fresh mock data only
Every run generates a brand-new mock user (timestamp email). No real people's data, and reruns never collide or create duplicate accounts.

    
No OTP or CAPTCHA bypass
The agent tests ordinary product flows. It does not try to defeat security checks.

    
Weak requests get stronger
"Just check the URL" can pass while the feature is broken, so a safety checker adds real checks and marks them so you can see what changed.

    
Honest failures
When the app changes (like a renamed button), the test fails on purpose and names the exact element it could not find.

    
Everything recorded
Source URL, retrieval time, selectors, code, run times and explanations are all kept with each run.
